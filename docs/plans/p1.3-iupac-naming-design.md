# P1.3 — Structure → Name (algorithmic IUPAC engine) · Design

Status: design approved (architecture + tier order). This document specs the
engine and **Tier 1** (acyclic skeletons). Later tiers get their own specs.

## Goal

When the user draws a structure, produce its **IUPAC name** by computation
(offline, no DB, no network) — the structure→name half of DChemInk, mirroring
the existing name→structure (P1.2). Names target the **Preferred IUPAC Name
(PIN)** and ChemDraw's default locant style (locant adjacent to the part it
modifies: `pent-2-ene`, `hexan-3-ol`, `2-methylbutane`).

All rules are **re-derived from the public IUPAC recommendations**. We may
*observe* a reference engine's output to sanity-check a tricky case, but copy no
code or data from any proprietary editor.

## Ground rules honored

- **Tier 0 / browser-only.** Pure computation on the drawn graph. No backend,
  no paid API. (OPSIN, used for verification below, is a bundled JS asset, not a
  network call.)
- **Original work only.** Rules authored from the IUPAC Blue Book.

## The tier staircase (each = its own spec → plan → commit)

| Tier | Covers |
|---|---|
| **T1 (this spec)** | Acyclic hydrocarbon skeletons: principal-chain selection, lowest-locant numbering, alkyl substituents, di/tri… multipliers, `-ene`/`-yne` unsaturation. |
| T2 | Principal characteristic groups + seniority (acid > ester > amide > nitrile > aldehyde > ketone > alcohol > amine), suffix vs. prefix, parent chain must contain the senior group. |
| T3 | Monocyclic: cycloalkanes; benzene + retained names (toluene/phenol/aniline/benzoic acid); o/m/p & numbered substitution. |
| T4 | Fused/bridged/spiro carbocycles; heterocycles (Hantzsch–Widman + retained); von Baeyer. |
| T5 | Stereodescriptors (R/S, E/Z, cis/trans), then the long tail. |

The **architecture below is constant across all tiers**; only the rule coverage
inside the engine grows.

## Architecture

Three isolated units:

### 1. `src/chem/naming/graph.ts` — the normalized molecular graph

A plain data model the engine consumes. No RDKit, no Ketcher, no DOM — so the
engine is unit-testable with hand-built fixtures (same style as the existing
`KetDoc` tests).

```ts
export interface NamingAtom {
  index: number;        // 0-based, stable
  element: string;      // "C", "O", "N", ...
  charge: number;       // 0 for T1
  hydrogens: number;    // total H count (implicit + explicit)
  aromatic: boolean;    // false for T1; carried for later tiers
  ringIds: number[];    // SSSR ring memberships; empty for acyclic
}
export interface NamingBond {
  from: number;         // atom index
  to: number;           // atom index
  order: 1 | 2 | 3;     // kekulized for naming
  aromatic: boolean;
}
export interface MolGraph {
  atoms: NamingAtom[];
  bonds: NamingBond[];
  fragmentCount: number; // disconnected components
}
```

### 2. `src/chem/naming/adapter.ts` — perception adapter (the only RDKit touch)

Builds a `MolGraph` from a molblock/SMILES using **RDKit-JS for perception**
(`get_json()` / `get_molblock()` for atoms, bonds, H-counts; SSSR ring info and
aromaticity for later tiers). Isolated here so the rules engine never calls
RDKit directly and RDKit stays swappable.

### 3. `src/chem/naming/engine.ts` — the rules engine (grows per tier)

```ts
export type NameStatus = "named" | "unsupported" | "empty" | "error";
export interface NameResult {
  name: string | null;
  status: NameStatus;
  reason?: string;        // when unsupported, e.g. "contains a ring (Tier 3)"
  verified?: boolean;     // OPSIN round-trip matched the input
  parentChain?: number[]; // chosen main-chain atom indices (for highlight, T1+)
}
export function nameMolecule(graph: MolGraph): NameResult;
```

### 4. `src/chem/naming/verify.ts` — OPSIN round-trip correctness gate

After the engine produces a candidate `name`, parse it **back** to a structure
with OPSIN (a bundled JS build of OPSIN — name→structure) and compare its
InChIKey to the input's InChIKey (via RDKit):

- **Match** → `verified: true`; surface the name with a "✓ verified" badge.
- **Mismatch / OPSIN unavailable** → do **not** emit a possibly-wrong name;
  return `status: "unsupported", reason: "could not verify"`. We never show a
  name we can't round-trip.

This is the feature that lets us *guarantee* correctness rather than hope for
it, and it doubles as the automated test oracle. OPSIN integration also advances
the offline P1.2 packaging goal. The verifier is behind an interface so the
engine is testable without OPSIN loaded; if the asset is absent at runtime, the
app still emits names but without the verified badge (degrade, not fail).

### 5. UI — live "IUPAC name" row in the Properties panel

Debounced on Ketcher's `change` event (same pattern as the formula/MW captions
in P1.1). Reads the current structure, runs adapter → engine → verifier, shows:
- the name + "✓ verified" badge, or
- "not yet supported — \<reason\>" (transparent diagnostics).

## Tier 1 algorithm (acyclic hydrocarbon skeletons)

**Accept** only: single connected fragment, atoms ∈ {C, H}, no rings, no
charges, no isotopes. Anything else → `unsupported` with a specific reason
("contains nitrogen — functional groups arrive in Tier 2"; "contains a ring —
Tier 3"; "multiple fragments — Tier ≥2").

On an accepted graph:

1. **Carbon skeleton.** Reduce to the carbon graph (H implicit). It is a tree
   (acyclic).
2. **Principal chain selection** (IUPAC P-31.1 subset, applied in order until a
   single chain wins):
   a. greatest number of skeletal atoms (longest chain);
   b. greatest number of skeletal multiple bonds (ene + yne);
   c. lowest locants for the multiple bonds as a set (ene preferred over yne at
      first point of difference);
   d. greatest number of substituents cited as prefixes;
   e. lowest locants for those substituents;
   f. lowest locant for the substituent first in alphanumeric order.
3. **Numbering.** Number from the chain end giving the lowest locant set —
   compared first on the multiple-bond locant set, then the substituent locant
   set, then alphabetical first-point-of-difference.
4. **Substituents.** Each branch off the chain is named as an alkyl substituent
   (recursively, by the same chain logic): `methyl`, `ethyl`, `propyl`,
   `propan-2-yl`, `2-methylpropyl`, … (systematic PIN substituent names; a
   retained-name toggle — `isopropyl`/`tert-butyl` — is deferred).
5. **Assembly.** `prefixes` (alphabetized; multiplying prefixes di/tri/tetra…
   not counted in alphabetization) + locants + parent stem
   (`meth/eth/prop/but/pent/hex/hept/oct/non/dec…`) + unsaturation ending
   (`-ane` / `-ene` / `-yne`, with locants and multipliers, e.g. `-2,4-diene`).
   Apply locant elision/standard punctuation.
6. **Verify** via OPSIN round-trip (see above) before returning.

### Tier 1 explicitly out of scope

Rings, heteroatoms, any functional group, charges, stereochemistry,
multi-fragment inputs, isotopes. All return `unsupported` with a reason.

## Testing strategy

- **Engine unit tests** on hand-built `MolGraph` fixtures (no WASM): a corpus of
  SMILES→expected-name pairs covering alkanes, branched alkanes, alkenes,
  alkynes, dienes, tie-break cases (chain selection, numbering direction,
  alphabetization). Sourced from IUPAC examples / textbooks.
- **OPSIN round-trip oracle**: for every corpus entry, the generated name must
  round-trip to the input InChIKey (catches engine bugs automatically).
- **Adapter tests**: molblock/SMILES → expected `MolGraph`.
- **Rejection tests**: ring / heteroatom / charged / multi-fragment inputs
  return the correct `unsupported` reason.
- Existing Vitest + Playwright setup; no new infra beyond the OPSIN JS asset.
