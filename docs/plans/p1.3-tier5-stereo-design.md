# P1.3 Tier 5 — Stereodescriptors (R/S, E/Z)

> Original work re-derived from the public IUPAC recommendations. CIP priority
> ranking is universal chemistry; we use RDKit's well-tested CIP implementation
> (allowed — same posture as using RDKit perception throughout the engine).
> Never copied from ChemDraw.

## Goal

Add absolute stereodescriptors to names the engine already produces:
- **R/S** tetrahedral stereocenters → `(2S)-2-aminopropanoic acid`
- **E/Z** double bonds → `(E)-but-2-ene`, `(2Z)-...`
- Combined / multiple → `(2R,3S)-...`, `(2E,4Z)-...`, `(1R,2S)-...`

## Source of truth: RDKit CIP

RDKit `JSMol.get_stereo_tags()` returns:
```
{ "CIP_atoms": [[atomIdx, "(R)"|"(S)"], ...],
  "CIP_bonds": [[a1, a2, "(E)"|"(Z)"], ...] }
```
- Labels are returned ONLY for stereo that is SPECIFIED in the input (via @/@@,
  /\, or a wedge in an imported molblock). Unspecified centers get NO label →
  we emit NO descriptor for them (the constitution name is still correct). This
  preserves the no-wrong-names invariant: we never invent a configuration.
- We trust RDKit's CIP assignment verbatim. We do NOT re-derive CIP priorities.

## Architecture

- **adapter.ts**: after parsing, read `mol.get_stereo_tags()`, strip the
  parentheses, and attach to `MolGraph`:
  - `stereoAtoms?: Map<number, "R" | "S">` (atom index → label)
  - `stereoBonds?: { a: number; b: number; label: "E" | "Z" }[]`
- **graph.ts**: extend `MolGraph` with the two optional fields.
- **engine.ts / assemble.ts**: after the locant numbering is fixed, translate
  stereo atom/bond indices to locants and build a single front descriptor.

## Descriptor assembly rules (verify each against PubChem)

- Front of the name, in one parenthesised, comma-separated, locant-sorted group:
  `(<locant><label>,<locant><label>,...)-` e.g. `(2S,3R)-`, `(2E,4Z)-`.
- **Stereocenter locant** = the parent locant of the stereogenic atom (chain or
  ring numbering already computed).
- **Double-bond locant** = the lower locant of the two double-bond atoms (same
  number used for the `-ene` locant).
- **Locant omission**: when the molecule has exactly ONE stereo element and the
  parent offers no ambiguity, PubChem still usually cites the locant if the name
  carries locants (`(2S)-`). For a lone C=C whose ene-locant is already implied
  (e.g. but-2-ene), PubChem uses `(E)-but-2-ene` (bond descriptor without its
  own locant) when there is a single double bond — confirm empirically and match.
- Mixed atom+bond descriptors are merged and sorted by locant in the SAME group.
- Numbering tie-breaks: stereo does NOT change the chain/ring numbering chosen by
  earlier rules in this engine (lowest locants to PCG/unsaturation/prefixes).
  We only read locants out; we do not let R/S/E/Z drive numbering (a later
  refinement if PubChem disagrees on specific cases).

## No wrong names

- Emit a descriptor only for atoms/bonds RDKit labelled. Partial specification →
  partial descriptors (matches PubChem).
- If RDKit reports a stereocenter as specified but returns no CIP label
  (unassignable), emit no descriptor for it (name remains constitutionally
  correct).
